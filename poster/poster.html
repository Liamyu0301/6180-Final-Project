Does memory format matter under repeated compression?

Only when the memory is written once. Rewriting it after every session costs 6 to 21 points of accuracy in every format, and erases the gap between prose and JSON.
Cheng Xin · Mengli Yu · Jia Song
github.com/Liamyu0301/6180-Final-Project

1 The problem

A chat agent cannot keep a long conversation in its context forever. It compresses the history into a short memory, then rewrites that memory again and again as the conversation grows.
How much does it forget, and does the format of the memory change that?

2 Method

1
Take a long conversation
10 LoCoMo conversations, 19 to 32 sessions and 19K to 36K tokens each.
2
Compress it into a memory
Claude Haiku 5.5 writes a memory of 1/4, 1/10 or 1/20 of the history's tokens, in one of 3 formats. Either once, from the whole history, or rewritten after every session (19 to 32 rewrites) to the same final size.
3
Answer from the memory alone
Haiku answers 1,540 questions about the conversation and sees only the memory.
4
Judge every answer
Claude Sonnet 5.5 marks each answer right or wrong, and labels why each wrong answer was wrong.
Two baselines
Full history: no compression, the ceiling.
Retrieval: BM25 picks raw turns for each question, filled to the same token budget as the memory.
Three memory formats, same token budget
Prose
Free-form paragraphs.
JSON
One object with facts, preferences, state_updates, timeline.
Anchors + summary
Word-for-word quotes for numbers, dates and names, then a short summary of the rest.

4 Analysis

What the numbers mean
Every rewrite loses facts. At the same final size, a memory rewritten after every session scores 6 to 21 points below one written once, in all 3 formats at all 3 ratios.
Format matters only until you rewrite. Written once, prose beats JSON by 11 points at 4x and 10x. Rewritten every session, the two are tied.
Errors are loss, not confusion. In 80% of wrong answers the fact is simply gone. Only 2% come from a memory that says something false.
What failed or surprised us
Compression lost to plain retrieval. BM25 over raw turns is level with the best memory at 4x and wins by 15 and 28 points at 10x and 20x. It had about a tenth more text, far too little to explain those gaps.
Quoting word for word did not protect facts. Anchors + summary was built to resist drift, yet it is the lowest of the three formats in every cell, often within the interval.
"More rewrites, lower accuracy" is clear only for prose. For JSON and anchors, going from every 4 sessions to every session is within noise.
What is still open
The judge is a model. Sonnet's right-or-wrong verdicts have not been checked against human labels yet.
Narrow evidence. One model family, one main benchmark, one sample of each memory; intervals come from 10 conversations.
Why does rewriting hurt? Untested idea: each rewrite keeps a fact only with some probability, so losses compound. A control that rewrites without adding a new session would test it.
Not a level field. Retrieval sees the question; the compressor never does.
